## Como vamos nos organizar

- **Ritual de reuniões**: acompanhamento assíncrono via issues e board do
  GitHub Projects, com 1 sync semanal para alinhar prioridades e destravar
  bloqueios.
- **Board**: GitHub Projects, com colunas Backlog / Em andamento / Em review /
  Concluído.
- **Regra de branch**: feature branches a partir de `main`, PR obrigatório
  com no mínimo 1 review aprovado antes do merge.
- **Regra de commit**: Conventional Commits (`feat:`, `fix:`, `docs:`,
  `refactor:`, `test:`, `chore:`, etc.).

## Decisões técnicas divergentes

Discussão assíncrona na issue relacionada; a decisão final é registrada como
um ADR em `docs/adr/`.
